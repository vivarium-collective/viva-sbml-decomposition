Arm 8 — Multi-organ scaling (where monolithic Tellurium strains)

As an SBML model grows large (tens -> hundreds -> thousands of species), where does a monolithic libroadrunner/CVODE instance strain — in model BUILD (compile) time, in integration time, or both — and does decomposing the body into N per-organ process-bigraph sub-processes coupled through a shared store actually come out ahead end-to-end, or does it just move the cost around?

Claim. The one strong, well-measured result is that the MONOLITHIC libroadrunner BUILD strains superlinearly in the reaction count: 0.20 s at 97 species -> 1.76 s at 385 -> 5.54 s at 769 -> 18.5 s at 1537 species (~94x for ~16x the reactions, ~O(N^1.64)), with the dense-CVODE run blowing up alongside it (0.0023 s -> 2.56 s). That is the real strain point and the reason a very large SBML model is painful to run monolithically. Decomposition is NOT a free win: building N small models is SLOWER than the single compile up to ~100 species (1.7x slower at 97 species), reaches only rough parity at 385 species (1.40 vs 1.76 s) and becomes a clear build win only at ~1500 species (2.4x); and the decomposed per-tick RUN overhead is ~16x the monolith's CVODE run, so the decomposed body is SLOWER END-TO-END at every N measured (decomp_total 2.35 s vs mono_total 1.81 s at 385 species). The end-to-end gap narrows with N but the decomposed run is unmeasured past N=128, so no end-to-end crossover is claimed. Decomposition is a structural trade — it swaps the monolith's superlinear build for much higher run overhead — that would only pay off end-to-end on models larger than measured. CRUCIAL caveat: the additive-split accuracy is good only at small N / fine interval (max_rel_err 2e-3 at N=2, 1.2e-2 at N=8, 5.2e-2 at N=32) and is 0.31 (31%) at N=128 — so the regime where the speed gap narrows and the regime of acceptable accuracy do NOT co-occur at a fixed coupling interval. All numbers measured, not fabricated.

What this arm shows

The strain curve — monolithic compile explodes, decomposition stays cheap

Composability — why decomposition is the way out at scale

Findings

  • STRONG RESULT — the monolithic libroadrunner BUILD (compile) strains superlinearly: measured medians 0.20 s at 97 species, 1.76 s at 385, 5.54 s at 769, 18.5 s at 1537 species — ~94x the build cost for ~16x the reactions (~O(N^1.64)). The dense-CVODE integration blows up alongside it (0.0023 s -> 0.058 s -> 0.395 s -> 2.56 s). Both halves of the monolithic cost grow superlinearly; this is the real, well-measured strain point and the arm's headline.
  • HONEST NEGATIVE — decomposition does NOT build "several-fold faster by hundreds of species". The decomposed build is N separate libroadrunner setups: SLOWER than the single monolithic compile up to ~100 species (97 sp: 0.34 s vs 0.20 s, 1.7x slower), roughly at PARITY by 385 species (1.40 vs 1.76 s), and a clear win only at ~1500 species (7.75 vs 18.5 s, 2.4x). The build crossover is at the hundreds-of-species scale, not before.
  • HONEST NEGATIVE (end-to-end) — the decomposed per-tick RUN overhead dwarfs the monolith's raw CVODE run: at 385 species decomp_run 0.95 s vs mono_run 0.058 s (~16x). So the decomposed body is SLOWER END-TO-END at every N measured: mono_total vs decomp_total = 0.017 vs 0.044 s (N=2), 0.039 vs 0.143 (N=8), 0.200 vs 0.559 (N=32), 1.81 vs 2.35 (N=128). The end-to-end gap narrows as N grows (3.6x -> 1.3x), but the decomposed run is UNMEASURED past N=128 (too slow for the harness), so NO end-to-end crossover is claimed. Decomposition trades the monolith's superlinear build for higher run overhead; it would only pay off end-to-end on models larger than we measured.
  • The coupling is genuine: Glc_blood lives in ONE shared store and every organ writes the delta it produced on it, reconciled additively through the bigraph apply path (arm-3 pattern). The shared pool drains more as more organs are added (monotone in N — a test asserts 8 organs drain it below the 2-organ case), which is only possible if the organs genuinely share the pool (contrast arm 7's N INDEPENDENT monoliths).
  • CRUCIAL caveat — accuracy and speed do NOT line up. The decomposed-vs-monolithic max_rel_err is a first-order additive-split error: 2e-3 at N=2, 1.2e-2 at N=8, 5.2e-2 at N=32, 0.31 (31%) at N=128. It HALVES as the coupling interval halves (verified) and GROWS with coupling density (more organs competing for the one pool per interval). The N=128 point where the end-to-end gap is smallest is exactly where accuracy (0.31) is unusable — so the speed crossover regime and the acceptable-accuracy regime do not co-occur at a fixed interval. Restoring accuracy at large N needs a finer interval, which adds more ticks and makes the decomposed run even slower. This is why the study verdict is PARTIAL.

enzymes? Testing biochemistry.** 
*Teusink,B et al.: Eur J Biochem 2000 Sep;267(17):5313-29.* 
The model reproduces the steady-state fluxes and metabolite concentrations
of the branched model as given in Table 4 of the paper. It is derived from the model
on JWS online, but has the ATP consumption in the succinate branch with the same
stoichiometrie as in the publication. The model was successfully tested on copasi
v.4.4(build 26).

reaction (Keq = 1.45\*10 4 ). The value used in this model is for the

Authors of the publication also mentioned a few misprints in the original
article: 
in the kinetic law for *ADH* : 

1. the species *a* should denote *NAD* and *b* *Ethanol*
2. the last term in the equation should read *bpq* /( *K ib K iq K p* ) 

in the kinetic law for *PFK* : 

1. R = 1 + λ 1 + λ 2 + g r λ 1 λ 2
2. equation L should read: L = L0\*(..) 2 \*(..) 2 \*(..) 2 not L = L0\*(..) 2 \*(..) 2 \*(..)
