Monolithic Tellurium (reference)

Does the whole SBML model, integrated in one libroadrunner/CVODE call through a single TelluriumProcess, reproduce the model's reference trajectory, and what is its performance baseline?

Claim. Monolithic Tellurium reproduces the reference to ~1e-6 and is the fastest arm — the speed + accuracy reference.

What this study shows

The glycolysis trajectory this study runs exactly

Runtime — framework share per study

Where the time goes — process vs framework

Findings

  • Matches direct libroadrunner to max_rel_err ~1e-6 on a shared grid (rtol 1e-6, atol 1e-9).
  • overhead_fraction ~0.32 (highest of all arms): the single CVODE call is so cheap that framework time dominates its share — framework SHARE is largest for the cheapest process, not the most decomposed.
  • Bulk-port binding (viva-tellurium bulk_species + Array species leaf, libroadrunner bulk C API) makes sbml-in-tellurium ~12% faster wall-clock, BIT-IDENTICAL (max abs trajectory diff 0.0). The win lands in total runtime, not overhead_fraction (which stays ~0.32) — a real speedup that doesn't move the framework SHARE, reinforcing that share != cost.
